# 指定歷史來源與跨瀏覽器同步

## 管理者啟用

1. 在資料較完整的電腦，重新整理該網站所有研究、監控分頁，開啟「資料品質」。
2. 複製「本機來源代碼」（`MD1-` 加 64 位小寫十六進位字元）。代碼是瀏覽器 Cookie 識別的單向雜湊，不是密碼或登入憑證。
3. 由 Sites 專案管理者將正式環境變數 `MARKET_HISTORY_PRIMARY_SOURCE` 設成完整代碼，再部署已保存版本以套用設定。保留其他環境變數，不變更密碼、Token、登入期限或 Railway 收集器。
4. 確認指定電腦顯示「指定歷史上傳來源」，其他電腦顯示「下載與本機收集，不上傳」。指定電腦仍須有效七天登入及 Railway 比對。

未設定環境變數時為過渡模式，沿用原本合格收集者上傳。錯誤格式會停止所有瀏覽器上傳，但公開下載繼續；移除變數會回到過渡模式。更換指定電腦時直接更新為新代碼，不必先清空設定。一般網站 API 不提供來源綁定權限。

來源代碼綁定同網站、同瀏覽器設定檔的 `md_client` HttpOnly Cookie，不是硬體認證。清除 Cookie、更換瀏覽器或無痕模式需重新綁定。登入更新不改來源代碼，不會自動延長授權。

## 補傳與保存語意

來源設定改變後，單一主控分段盤點全部本機歷史，每輪最多 64 個 15 分鐘區塊，可重新載入續跑。每 30 秒最多送一批、最多八區塊，壓縮上限 256 KiB、解壓上限 1 MiB，新資料先送；大筆舊歷史可能需要數小時。

回覆區分完整保存、相同數值保存但來源未獲最終驗證、較高品質版本取代與衝突。處理標記綁定本機區塊版本、來源設定和雲端版本，避免重複傳送；任何新本機修正會重新排入。處理標記不授予容量清理資格，Railway 最終資料只由伺服器已驗證快取建立，包含其中的 `null`。

## 下載

公開讀取不需登入或來源資格。下載佇列獨立於上傳排程，最多兩個並行讀取，每輪最多八區塊、輪間 500ms；讀取啟動間隔至少 450ms，保留全站 API 額度。背景維持低頻同步；429 遵循 Retry-After，網路錯誤退避並由已保存游標續跑。

下載會核對區塊、索引版本與 SHA-256。平行工作只有成功的連續版本前綴可以推進游標，舊主控不得寫入。顯示已讀區塊、可用分鐘、雲端缺格、缺值及衝突；最早／最晚區塊不等於連續完整資料。仍沿用本機 200／180 MB 保護與按需載入，原始掛單簿、每秒輪廓與私人設定不公開保存。

價格覆蓋與深度覆蓋分開判斷。索引的可選 `candleMasks` 依 BTC／ETH／SOL 順序列出 15 分鐘內已收盤、完整的一分鐘價格位元；只有深度的區塊為零。價格補抓可跨越只有深度的區塊，單次仍以 200 分鐘為限，碰到該商品已存在的完整雲端價格才停止並優先讀取。舊版伺服器缺少此欄位時維持保守區塊界線；不使用其他商品的覆蓋、不推算缺少的 OHLCV。此修正解決「完整深度索引使 K 線每 30 秒只能補約 15 分鐘」的慢速回補，沒有提高上傳頻率或放寬收集資格。

下載統計僅使用雜湊核對後的雲端區塊，以區塊版本保存獨立覆蓋摘要；不能以合併本機後的內容推算。切換區間時沿用相同雲端版本摘要；沒有摘要時重新讀取，尚未上傳的本機價格不能列為雲端保存。舊統計重新盤點，行情與本機唯一資料不刪除。
