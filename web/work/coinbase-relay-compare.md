# Coinbase Sites 中繼與手動比對修正

基準 v58 / 286429141f703b1ef42f19f523bdac1bb8ca2503。使用者要求直接實作 Sites 串流中繼，另修正「比對並補齊」偶爾沒有反應。

## 約束

- 沿用現有 Sites 專案、公開存取與登入期限；不新增 Railway 或其他付費服務、不修改插件。
- 三商品九份掛單簿持續運作；中繼替換 Coinbase 傳輸，不另開平行交易所收集者。REST 備援保留真實時間。
- 不修改本機 DNS、安全設定或略過憑證驗證。現有資料及設定保留。
- 研究分鐘取樣 ±1.5 秒、監控核心 30 秒與每秒輪廓維持。
- 本機測試停用 Railway、不上傳測試資料；必要正式驗證沿用 Sites 既有節流。

## 已驗證

- 官方 Cloudflare WebSocket 文件支援 Worker 端連出與接受 101，Sites 對外長連線尚未實測。
- 正式 ETH / 2W / 1m 的資料品質面板，按「比對並補齊（645 格）」後只有原按鈕文字，沒有開始、等待或錯誤訊息；實際 DOM 回饋驗收已失敗。
- 已重現實際後端契約錯誤：2W 1344 個 have 鍵仍小於既有 256KiB 請求上限，但超過固定 1024 筆，被 worker/index.ts 回 HTTP400 BAD_QUERY。test/history-regression.test.ts 新增 14D 測試已跑紅。
- useMarket.ts 的 startManual 在 historyStopped、nextRepair、starting、advancing 或 restoring 時直接 return；送出前也沒有 React 進度狀態，catch 只設歷史錯誤旗標，QualityPanel 不顯示 historyError。
- startManual 的工作需求判斷硬編碼目前引擎商品、ALL4 與 zone0，可能與品質面板選擇的商品／來源／指標不一致。

## 實作決策（尚未完成）

- 保留 256KiB 請求上限，舊 have 陣列可放寬至 4096（仍受原請求大小限制），修復既有2W／1M客戶端。
- 新增可選 compact ACK：對確切 from/to 範圍內、已保存的來源 id:sha 鍵排序去重，以 SHA256 綁定鍵清單，再傳位元圖表示本機持有項目。最多涵蓋半年，幾 KiB 即可處理 17k 區塊；來源鍵集合變更回409並重新取得狀態，不截斷 have 造成重送迴圈。不新增 DB 表。
- startManual 送出前即時顯示 starting；冷卻、授權、錯誤均有明確狀態。明確使用者重試可解除過去HTTP永久停止，但儲存／契約驗證失敗不可繞過。面板帶入其實際 asset/venue/zones。
- 中繼擬用固定 Coinbase 上游 WebSocket、同來源入口；不轉送 Cookie/Authorization，不成為任意代理。限制公開訂閱訊息大小、頻道與商品數；雙端關閉清理。先實測 Sites Upgrade，若不支援才評估 SSE，不宣稱已完成。
